# デジタルサイネージシステム 製品仕様書・運用マニュアル

## 1. システム概要

本システムは、工事現場に設置したWindows 11のデジタルサイネージと、FastAPI製の遠隔管理サーバーで構成されます。管理画面から物件情報とPDF資料を登録でき、サイネージはサーバーから配信されたPDFをループ表示します。

**主な構成要素**：

- **サーバー**：`server.py`（FastAPI、SQLite）
- **サイネージクライアント**：`signage_app.py`（PySide6）
- **対応資料**：A3中央、A4左、A4右の3区画に分けたPDF
- **データベース**：`contact_board.db`
- **サーバー側ファイル保存先**：`server_storage/<物件ID>/`
- **クライアント側キャッシュ**：`signage_storage/<物件ID>/`

## 2. 今回の実装内容

### 2.1 `server.py` の変更点

- SQLiteにユーザーと物件を登録する初期化処理を追加。
- bcrypt（Passlib）によるパスワードハッシュ化とログイン／ログアウトを実装。
- ログインユーザーのCookieを利用した管理画面アクセス制御を実装。
- ユーザーごとに所有物件だけを表示・操作するマルチテナント分離を実装。
- 物件ごとに40文字のサイネージ認証トークンを発行。
- サイネージAPIで物件IDとトークンを検証し、許可された資料情報だけを返却。
- A3・A4左・A4右の物件別フォルダを自動作成し、PDFの一覧取得、アップロード、削除に対応。
- 管理画面から物件情報の作成・更新・削除に対応。
- 物件削除時は、データベースのレコードとサーバー上の物件フォルダをまとめて削除。
- PDFのドラッグ＆ドロップによるアップロードに対応。
- `/mobile/{project_id}` で、認証なしの住民向け資料一覧画面を提供。
- AWS EC2ではIMDSv2からパブリックIPを取得し、スマートフォン用URLを自動生成。取得できない環境では `127.0.0.1` を使用。
- `0.0.0.0:8000` での起動に対応。

### 2.2 `signage_app.py` の変更点

- `--id`、`--token`、`--server`、`--kiosk` のコマンドライン引数に対応。
- `--token` を必須とし、物件ごとの認証トークンをAPIリクエストに付与。
- 起動時に画面サイズから倍率を計算し、4Kを含む16:9画面へレイアウトを比例拡大。
- ヘッダーに物件名、工事用掲示板タイトル、日付、工期、現場代理人、連絡先を表示。
- A4左・A3中央・A4右の3区画を25%・50%・25%の比率で固定配置。
- PyMuPDFでPDFの1ページ目を高精細に画像化して表示。
- 区画ごとに資料を独立してループし、サーバーから指定された秒数で切り替え。
- サーバーの最新資料一覧にないローカルPDFを自動削除し、キャッシュを同期。
- 物件別のローカルキャッシュにより、通信が一時的に失敗しても既存資料を表示。
- フッターに工事中画像、物件別QRコード、天気表示、会社ロゴを配置。
- `--kiosk` 指定時は枠なし・最前面・フルスクリーンで起動。
- キオスクモードでも `Esc` または `Ctrl+Q` で安全に終了可能。
- ウィンドウのリサイズ時に、区画・ヘッダー・フッターを再配置。

## 3. 必要な環境とインストール

### 3.1 サーバー

- Python 3.10以降
- FastAPI
- Uvicorn
- Passlib（bcrypt）
- python-multipart

```bash
python -m venv venv
# Windows
venv\Scripts\activate
# Linux / macOS
source venv/bin/activate

pip install fastapi uvicorn passlib[bcrypt] python-multipart
```

起動：

```bash
python server.py
```

ブラウザで `http://127.0.0.1:8000/login` を開きます。

### 3.2 サイネージクライアント

- Python 3.10以降
- PySide6
- Requests
- PyMuPDF
- qrcode

```bash
pip install PySide6 requests PyMuPDF qrcode[pil]
```

## 4. サイネージの起動方法

```bash
python signage_app.py --id 1 --token <物件固有のトークン> --server 127.0.0.1:8000 --kiosk
```

| 引数 | 必須／任意 | 説明 |
| :--- | :--- | :--- |
| `--id` | 任意（既定値: `1`） | 接続対象の物件ID |
| `--token` | **必須** | 物件固有の40文字トークン |
| `--server` | 任意（既定値: `127.0.0.1:8000`） | サーバーのIPアドレスまたはドメインとポート |
| `--kiosk` | 任意 | フルスクリーン・最前面表示 |

Windowsの自動起動例（`start_signage.bat`）：

```bat
@echo off
cd /d D:\TAIHEI
call venv\Scripts\activate
python signage_app.py --id 1 --token <物件固有のトークン> --server 13.196.186.120:8000 --kiosk
```

このバッチファイルのショートカットを `shell:startup` フォルダへ配置すると、Windowsログイン時に自動起動できます。終了する場合は `Esc`、または `Ctrl+Q` キーを押してください。

## 5. 管理画面の使い方

### 5.1 初回ログイン

1. `/login` を開き、ユーザーIDとパスワードでログインします。
2. 初回起動時、データベースが空の場合はデモ用アカウントが自動作成されます。

**デフォルトアカウント**：

- ユーザーID：`admin` ／ パスワード：`admin123`
- ユーザーID：`user2` ／ パスワード：`pass123`

本番環境では、これらの初期パスワードをそのまま使用せず、必ず変更してください。

### 5.2 新規ユーザーの登録（`create_user.py` の使い方）

デモアカウント以外の新しいユーザーを追加する場合は、`create_user.py` を実行します。

```bash
python create_user.py
```

実行すると対話形式で入力を求められます：

```
--- 👤 コンタクトボード 新規ユーザー登録 ---
希望するユーザーIDを入力してください: newuser
パスワードを入力してください: newsecurepass
🎉 ユーザー「newuser」の登録が完了しました！
```

**機能**：

- bcryptアルゴリズムでパスワードを安全にハッシュ化してデータベースに保存
- 同じユーザーIDが既に存在する場合はエラーを表示
- ユーザーID・パスワードの両方が入力されていない場合は警告を表示

登録されたユーザーは、その直後から `/login` で新規ユーザーIDとパスワードでログイン可能になります。

### 5.3 物件の登録・管理

1. ログイン後、`/admin` で管理対象の物件を選択します。
2. 物件名、工期、現場代理人、連絡先、所在地、資料の切替秒数を登録・更新します。
3. A4左、A3中央、A4右の各枠へPDFをドラッグ＆ドロップします。
4. 物件設定画面に表示されるサイネージ起動コマンドを、現場PCのバッチファイルへコピーします。
5. 物件を削除すると、登録済みPDFとサーバー上の物件フォルダも削除されます。削除操作は取り消せません。

## 6. API・URL

| URL | 用途 |
| :--- | :--- |
| `GET /login` | ログイン画面 |
| `POST /login` | ログイン処理 |
| `GET /logout` | ログアウト |
| `GET /admin` | 管理画面 |
| `GET /api/signage-data/{project_id}?token=...` | サイネージ用物件情報・資料一覧API |
| `GET /files/{project_id}/{folder}/{filename}` | PDFファイル配信 |
| `GET /mobile/{project_id}` | 住民向けスマートフォン画面 |

サイネージAPIは、物件IDに加えて物件固有のトークンが一致した場合だけデータを返します。トークンは第三者へ公開しないでください。

## 7. AWS本番運用

推奨構成は、Amazon EC2（Ubuntu）で `server.py` を常駐させ、セキュリティグループで必要なポートだけを公開する構成です。実運用では、次の対策を実施してください：

- HTTPS（リバースプロキシ、Route 53、ACM等）を利用する。
- SQLiteと `server_storage` を定期バックアップする。
- 初期デモアカウントを変更または削除する。
- 8000番ポートを直接インターネットへ公開せず、必要に応じてNginx等を前段に配置する。
- サイネージトークンをログや画面共有に出さない。
- `server_storage` とデータベースへのアクセス権を限定する。

systemd等で常駐化する場合は、仮想環境のPythonからUvicornを起動し、作業ディレクトリ、環境変数、ログ出力先を明示してください。
